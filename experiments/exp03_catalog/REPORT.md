# Exp03 実行レポート: OS指標による都市形態カタログ

**実行日**: 2026-07-08（14:24 初版 → 17:20 再構成 → 17:55 最終版） /
**データ**: global_v2 全球層化サンプル（exp01と同じ解析対象 10,050地点） /
**コード**: `build_catalog.py`（改善版、Λ̄対数変換・手法グループ順並べ替え）

## TL;DR

> OS9次元ベクトルをKMeans（K=6）でクラスタリングすると、世界の集落は
> **密度と連結ダイナミクスの両軸で分かれる6タイプ**に整理できる:
> 中密2タイプ（格子核型・凝集放射型、γ/W_transで区別）、疎2タイプ（街道散在型・山間散村型、
> Λ̄と連結の緩慢さで区別）、高密1タイプ（稠密市街型）、そして際立った偏りのない
> 標準中密型。**密度だけでは中密2タイプ・疎2タイプの内部を分けられず、
> exp01の主張（ダイナミクス指標が固有情報を持つ）と整合する形でクラスタが分離した。**

## 1. 設計（詳細は README.md）

- 9次元 OS ベクトル（exp01 `os_vectors.csv`）をそのまま利用、新規フェッチなし
- `lacunarity_mean` のみ対数変換してからz-score標準化（5桁レンジの外れ値対策）
- KMeans, K=6, seed=42。Kの選定は事前のエルボー法・シルエット確認は行っておらず、
  「論文の記述に使いやすい粒度」を優先した固定値（**要検証**、§4参照）
- クラスタは`value_counts()`降順でType1〜6に振り直し（sklearnラベルとは非対応）
- 代表地点はクラスタ重心に近い地点を各3件選び、`ops run`で実際にオーバーレイ画像を
  フェッチ（2回に分けて実施: `reps.yaml`18件全成功、`reps2.yaml`18件中15成功・3件skip）

## 2. 結果

6タイプの内訳・特徴プロファイルは [README.md](README.md) の表を参照。
可視化は `catalog.html`（PCA散布図・レーダー図・代表画像・9次元全値テーブルを含む）。

### 2.1 タイプの対立軸

| 軸 | 分かれ方 |
|---|---|
| 密度 | 疎（Type2, 6）— 中密（Type1, 3, 4）— 高密（Type5） |
| 連結の急峻さ（γ） | Type1（格子核）が最大（+0.7σ）。連結が計画的街区の内部で一気に進む |
| 連結の緩やかさ（W_trans） | Type3（凝集放射）+1.8σ、Type6（山間散村）+0.8σ。広い範囲で漸進的に連結 |
| 空隙のムラ（Λ̄） | Type2・6（疎2タイプ）が最大。Type5（稠密市街）が最小 |

**同じ密度帯（中密）でもType1とType3はγ/W_transで明確に分離**——これはexp01の
「iso-density帯内部の識別はダイナミクス指標が担う」という主張の、記述的分類による裏付け。

### 2.2 サイズ分布

Type1（3,066）とType2（2,360）で全体の54%を占め、Type5（822）・Type6（762）は
少数派。**「標準中密型」（Type4, 1,449）が最大クラスタではない**——すなわち
「典型」は必ずしも最頻ではなく、格子核型・街道散在型という**構造的に特徴的な
形態の方が全球ではありふれている**。

## 3. 解釈

1. exp01が示した「密度軸の両極端でダイナミクスが支配」は、exp03のクラスタ構造とも
   整合する: 疎側の2タイプ（Type2, 6）と中密の2タイプ（Type1, 3）は、いずれも
   密度がほぼ同じ帯にありながら連結ダイナミクスの違いで分離している
2. 「標準中密型」（Type4）の存在は、9指標すべてが平均的な"基準形態"が
   実在することを示す一方、それが最頻ではない点は「典型的な集落像」という
   直感に反する結果として、論文の記述（案3）で使える

## 4. 制約・既知の課題

- **K=6は固定値で、クラスタ数の妥当性検証（エルボー法・シルエット係数・
  gap statistic等）は未実施**。K=5やK=7で構造が大きく変わらないかの確認が必要
- 代表地点3件/クラスタは目視確認用のサンプルであり、統計的代表性は保証しない
  （クラスタ重心近傍を機械的に選定）
- カタログHTMLの目視最終確認が未完了（README.md参照、Type4の表示崩れ疑い）
- `reps2_run.log`でskipされた3件の原因未記録（フェッチ失敗か、建物ノード不足か
  不明。次回実行時にログを追うこと）
